# OpenCode Setup for Project Conventions

OpenCode (anomalyco/opencode) reads project conventions from several locations. Use these when running the interactive bootstrapper to configure the project for OpenCode.

## Discovery Order

OpenCode looks for rules files in this order (first match wins in each category):

### Project rules (in repo root, committed to git):
1. `AGENTS.md` — primary, recommended (generated by `/init` command or manually)
2. `CLAUDE.md` — Claude Code fallback, used if no AGENTS.md exists

### Global rules (user-specific, not committed):
1. `~/.config/opencode/AGENTS.md`
2. `~/.claude/CLAUDE.md`

## opencode.json `instructions` field

The `instructions` field loads full file content into every prompt. Keep it minimal — only short, high-signal files. For the `codebase-constitution` constitution, only AGENTS.md goes here (~200 tokens):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["AGENTS.md"]
}
```

## In-project documentation (via AGENTS.md)

Only AGENTS.md is loaded into every session. The rest of the constitution (architecture.md,
ontology.md, feature contracts under `docs/features/`, ADRs, parking-lot.md) lives
*inside* the project and is surfaced to the agent through **AGENTS.md's "Source of Truth" list** —
the agent reads a detail file only when it needs it. That is the correct pattern for in-project
docs and costs roughly AGENTS.md's ~200 tokens per turn.

**Do not** register these in-project files as `references`. OpenCode's `references` are for content
**outside** the current project (external directories or Git repositories) — see "References
System" below. Files the agent already sees with ordinary file tools don't need a reference.

**Token comparison (in-project docs):**

| Approach | Token cost per turn |
|----------|-------------------|
| `instructions: ["AGENTS.md"]` only; detail files via Source-of-Truth list (recommended) | ~200 tokens |
| `instructions` with all detail files eagerly loaded | ~4,000 tokens |

## Recommended Permissions

Set safe defaults that allow productive work while preventing accidents:

```json
{
  "permission": {
    "*": "allow",
    "bash": {
      "*": "ask",
      "git *": "allow",
      "grep *": "allow",
      "python3 -m pytest*": "allow",
      "npm test*": "allow"
    },
    "webfetch": "allow",
    "external_directory": "ask"
  }
}
```

This means:
- All file reads, edits, writes, and searches are automatic
- Safe commands (git, grep, tests) run without approval
- Unknown or destructive shell commands prompt for approval
- Accessing files outside the project asks before proceeding
- Use `opencode --auto` to auto-approve all non-denied permissions

## Agent Skills System

OpenCode discovers reusable SKILL.md files from:

| Location | Scope | Example |
|----------|-------|---------|
| `.opencode/skills/<name>/SKILL.md` | Project-specific | `.opencode/skills/create-endpoint/SKILL.md` |
| `~/.config/opencode/skills/<name>/SKILL.md` | Global | Reusable across projects |
| `.claude/skills/<name>/SKILL.md` | Claude Code compat | Cross-tool skills |
| `.agents/skills/<name>/SKILL.md` | Agent-agnostic | Max portability |

Skills are loaded on-demand via the native `skill` tool. Agents see available skills and load full content when needed.

Frontmatter requirements for SKILL.md:
- `name` — lowercase, hyphens/underscores, max 64 chars, matches directory name
- `description` — 1-1024 chars, shown in tool listing

## References System

Configure external directories or Git repos as references in opencode.json:

```json
{
  "references": {
    "docs": { "path": "./docs" },
    "shared-lib": { "repository": "github.com/org/shared-lib", "branch": "main" }
  }
}
```

References with a `description` field are automatically included in agent context. References without descriptions are available via `@` autocomplete.

## Key Differences from Claude Code / Cursor

- OpenCode uses `instructions` in opencode.json for supplementary files (not just AGENTS.md)
- OpenCode's skill discovery walks up directory tree to git worktree root
- OpenCode reads CLAUDE.md as a fallback when AGENTS.md doesn't exist
- Built-in agents: `build` (full access), `plan` (read-only), `explore`, `scout`, `general`

## `/init` Command

Run `/init` inside OpenCode's TUI to automatically generate AGENTS.md:
- Scans important files in the repo
- May ask a few targeted questions
- Creates or updates AGENTS.md with project-specific guidance
- If AGENTS.md already exists, improves it in place rather than replacing
